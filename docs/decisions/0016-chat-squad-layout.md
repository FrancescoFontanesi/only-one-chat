# 0016. Chat, Squad, and Settings from the design canvas

Status: Accepted (iteration 3). Supersedes the sidebar views in ADR 0012.

## Context

- **The user designed the interface** in the Claude.ai canvas for reorganizing Only One Chat's UI, with the Cyber Nihilism design system. It has three boards, Chat, Squad, and Settings. The rest are marked for removal.
- **The current backend defines the supported behavior.** The user asked to implement only what the backend can do where the canvas and backend differ.

## Decision

### Style

- **Copy canvas and design system CSS into `media/cn/`.**
  - `oo.css` contains the canvas's v4 stylesheet and design system tokens. Remove classes for the first graph-based Squad design, which no board uses, and the canvas's original Squad and Settings classes. Rebuild those views with design system references.
  - `bundle.css` contains the design system rules used here for buttons, tags, fields, frames, slabs, specs, meters, accents, the cursor, and Lattice. Omit the Google Fonts import and the corner marks the design system removed, leaving simple rectangular boxes.
  - `fonts.css` serves Rajdhani and JetBrains Mono (SIL OFL 1.1) from the extension because the webview CSP blocks network resources.
  - `app.css` adds what the real webview needs beyond the static boards. It covers full-height layout with scrolling confined to the thread, the composer and its controls, turn tool logs, popovers, motion, scrollbars, text options, the stepped meter, and responsive stacking in Squad and Settings.
- **Follow the VS Code theme.** Use Signal for dark themes and Print for light themes.
- **Rebuild design system motion in `webview/motion.tsx`.** The CSP blocks the inline styles written by `bundle.js`. Use the same algorithms and timings for Decode, Reveal construct and ascii, Type, Progress, Counter, Flash, and Scramble. Write only text nodes, classes, CSSOM properties, and canvas pixels. Disable motion with `prefers-reduced-motion`.
- **Use visible text choices.** In Squad and Settings, use the design system's text buttons (`Opts`, `role="radio"`). The active choice is in the ink color and enclosed in brackets, the others are muted, and hover inverts a choice. Reasoning and permissions use a stepped meter (`Scale`) with filled cells up to the selected level. On hover, additions show a 1-bit halftone and removals empty their cells, while Decode reveals the level name beside them. In chat, compact controls (`Pick`) show a key, one tick per option with the selection filled, and the selected name. Hovering over a tick displays it in halftone and decodes the corresponding option name, with its description beside it. Clicking a tick selects it, clicking the name advances to the next option, and arrow keys navigate. A new selection flashes once with inverted colors.
- **Draw the Lattice using `webview/lattice.tsx`.** The Lattice is the design system's alternate grid structure. It derives lines from actual cell geometry and draws shared edges once. Draw it as an SVG above the cells because `bundle.js` uses inline styles. Test the pure geometry in `latticeGeometry.ts`. As in the design system, broken lines are the default. The perimeter is open except for requested edges such as the shared line between stacked lattices. Leave 6 px clear on either side of the intersection pixel and center a 7 px plus sign there. This leaves 3 px between the plus and each line on both axes, including at corners. Skip this treatment for intersections less than 64 px apart on the same line and at inverted cell edges. Use whole pixels. At the user's request, draw each plus one shade above the lines it crosses (`--ink-disabled` over `--line` and `--ink-muted` over `--line-strong` in the focused composer). Continuous lines with perimeter nodes stay available as an option.
- **Limit layout and rendering work.** Redraw Lattice lines only when cell geometry may have changed, such as a resize of the root or a cell, or the addition or removal of a cell. Skip redraws when measurements stay the same. Previously each render or cell text change redrew the lines and forced layout for each response chunk and progress tick. The Squad board measures blocks only when they move or resize. Scroll the thread to the bottom at most once per frame. Compute each dial's fixed rim and markers once. Avoid Preact `memo` on thread items and dials. In Preact 10.29, children of a component that skips a render keep the parent from the earlier render. The retained parents added 20 MB in 60 seconds with Squad open.
- **Use motion within the design system's budget at the point of interaction.** Settings stay static. Decode text when it changes. The top status decodes on every change. Buttons scramble on hover through one listener for the view. Hovering over a message draws a stepped tick on its rule, inverts the author label, and reveals its actions. Composer options respond as described above, and its lines darken while typing. Construct animates items arriving in an open chat, such as a sent message, turn, report, facts, or changes. Existing content appears immediately when a chat opens. A running turn shows LIVE, a cursor, and a spinner on the latest action. The composer shows IN PROGRESS in cells. A permission request flashes three times using Flash. When the user opens Squad, frames enter with Reveal and model names decode. Masks read their colors once for the entire effect.

### Chat

- **Bar.** Show the folder, title, and status in the breadcrumb (READY, IN PROGRESS, WAITING FOR YOU, NOT READY), SIMULATION when using fake CLIs, HISTORY, + NEW, SETTINGS, and SQUAD with the pending-request count.
- **Single-column thread.** It extends past the composer by 15% of the composer's column on each side and stays within the dials. Without dials, the composer column is 70% of the panel. Below 640 px, both use the full width.
- **Messages.** Each message starts with an author, model, and status row with actions. Messages have COPY, and the user's messages also have ↺ RESTORE HERE. Show the route for turns, tools in a terminal-style log with recent actions visible during work and all available through + N ACTIONS, subagents, and a footer for context, output, time, and nominal cost. Delegations (D01) and reports (R01) are rows with expandable text. Show verified facts, changes, and notices. Informational events use a slim row, and errors offer RETRY and COPY DETAILS.
- **Dock.** Pending user decisions replace the composer. A permission request is the view's only Slab (keys 1, 2, 3, or Esc to deny). An editable delegation or report awaiting approval offers APPROVE, APPROVE ORIGINAL or APPROVE EDITED, and CANCEL. The composer fills the dock when there is no pending decision.
- **The composer is a Lattice cell** closed on all sides with a plus at each corner. Lines darken during typing and appear muted when the chat is unready. Below the text and an inset divider, one row shows the recipient (TO: LEADER or IMPLEMENTER, one per message), the route (name only, with ticks expanding upward on hover or focus), delegation approval as a `Pick`, the recipient's session context, and send. Type `@` and `/` directly into the composer. Text grows to about a third of the panel before it scrolls.
- **Two dials flank the composer** at widths of 1,000 px or more. They adapt the design canvas's v5 sidebar roles and usage board to the backend (`Hud.tsx`, with tested geometry in `hudGeometry.ts`). Both are 216 × 192 and sit 24 px from the composer, which shares their height. A dashed connector and an arrow link each dial to the center of the composer's nearest edge. A dial is part of a large circle with its center outside the view, facing the composer. Each option has a mark on a scale that rotates to the selection, with a fixed rim. Select through the label, dragging or scrolling the scale, or arrow keys. Controls stay visible and animate only when their values change, by rotating the scale, filling an arc, or decoding a name.
  - On the left, **R/ Talking to** selects the recipient through a label (LDR, IMP) or the outer ring (click or wheel). The scale rotates to the chosen recipient. The reticle controls reasoning through arcs for the model's levels, ascending from bottom to top. Drag or click a segment, use the wheel, or use arrow keys. The reasoning readout (RSN, level, position) sits above the middle divider under the name, provider, and status. Below the divider, show the model and, for the leader, a route selector that ADR 0018 replaces with delivery. The selected route sits in the center with the neighboring choices muted above and below. Use the wheel, click a neighboring choice, or use arrow keys. Changes step one row at a time. The leader keeps the chat's model. For the implementer, show a model switcher (↕ advances in the same session) and HANDOFF (ADR 0017). The composer's footer shows the recipient and route only when the dials are hidden.
  - On the right, **U/ Usage** starts with the recipient's provider and can rotate to the other one. It shows the five-hour window as a solid arc and number, the weekly window as a dashed arc with cells, and the reset time for the recipient's provider.
- **Explain why chat cannot start** (missing or untrusted folder) at the top of the thread, above the new chat.
- **`@` identifies files.** Each message has one recipient. The recipient is sent to the host and saved in the `to` field. Earlier saved chats with a leading `@impl` still read as they did before.
- **A leading `/` lists commands** for the route, recipient, attachments, new chat or stop, Squad, and Settings. Selecting a command updates the controls and removes it from the text. The host still interprets a fully typed command as a prefix.
- **Attachments.** Typing `@` opens the file list. A selected file appears as a chip above the composer. At send time the chips become a final line of `@path` mentions for the host to read as in ADR 0015. The thread renders the chips in place of that line.

### Squad

- **Overlay the chat with one contiguous Lattice panel** and a halftone scrim. Use shared lines and a plus at each intersection, including on the closed perimeter. Include the bar, the board header with legend and zoom, the board itself, the Events, Pending, and Changes tabs and list, the selected role's header and fields on the right, pending user decisions, and the footer. Pending decisions use the only accent, an inverted cell that flashes when a request arrives and stays plain when there is nothing pending. Agents on the board use cross-corner cards (`Crossed`) for the model, configuration, context, activity, subagents, and tokens. Select a role from its header. The selected role has ink-colored crosses. Remove the Models tab and event ticker. The usage panel (role context and provider windows) is deferred, and the host continues to send data (`TODO(squad)` in `App.tsx`).
- **Replace the Roles, Activity, and Usage sidebar views.**
- **Role fields write settings** as the Roles view did. The leader's model stays fixed for the chat, and a provider change applies to the next chat.

### Settings

- **Use the design system's printed Lattice slides** (RefLatticeSlidesPrint). Stack lattices along the same fourteen columns, with a 48 px margin, twelve content columns, and a second margin. Use broken lines with plus signs at intersections and dense cells. The cover has the brand, section links, and navigation (VS CODE ↗ and CHAT), a centered bracketed title with the section count and save scope, search, SAVE FOR (USER · FOLDER), and an inverted fake-CLI row. Each section has its own sheet with a header for index, title, ONLY/ONE · SETTINGS, and page number (02 / 04), margins, and a leading column with the title, purpose, and setting count. One oversized numeral extends below the leading column. Each setting's header shows the number and name, value source, and RESET above cells for the explanation and value. Roles use two entries, A and B, with the model and fields. The footer shows save scope and page number. Keep Settings static and omit Reveal and Decode. Below 900 px, every cell flows in order at full width.

### Canvas elements outside current backend support

- The block-and-reply-to-leader action.
- Automatic delegations as thread rows, since the backend does not report them.
- Message timestamps.
- The message queue.
- Status of completed subagents in the roles table, since Activity tracks active subagents only.

## Consequences

- **Add interface messages between the webview and host** (`showChat`, `manageTrust`, and `copy`). Chat receives the Squad data and controls (`roles`, `monitor`, `usage`, `setRole`, and `refreshModels`).
- **Read Codex usage** when chat opens and every two minutes while it is visible.
