## Risposta a plan (completed)

```text
Inserirei `include` nel livello che esegue gli script, in @main.py, prima della valutazione della singola riga.

Oggi `run_script` crea il dizionario delle variabili, lo passa a `evaluate` per ogni riga e continua dopo gli errori, restituendo infine un codice di fallimento. Richiamarlo direttamente per un file incluso creerebbe nuove variabili: serve invece un’esecuzione interna che condivida dizionario e contesto dei file.

Lascerei il calcolo delle espressioni in @evaluator.py e @lexer.py. La proposta è trattare `include` come direttiva dello script: non serve aggiungere stringhe al linguaggio delle espressioni.

Le scelte minori che propongo sono:

- Sintassi: `include "percorso"`, con spazi iniziali e finali ammessi; rifiutare percorso vuoto, virgolette mancanti e testo aggiuntivo. Nessuna interpolazione o espansione di variabili d’ambiente.
- Inclusioni annidate ammesse; lo stesso file può essere incluso più volte e viene rieseguito ogni volta.
- Rilevare i cicli fra i file attualmente in esecuzione, usando percorsi risolti: bloccare `A → B → A`, senza bloccare due inclusioni successive di `B`.
- Imporre anche una profondità massima: una catena lunghissima può esaurire le risorse pur senza cicli.
- Conservare le assegnazioni già eseguite quando arriva un errore: nessun rollback.
- Gli errori dei file inclusi devono indicare percorso, numero di riga e catena di inclusione.

Il rischio principale è che uno script possa aprire altri file accessibili al processo, anche fuori dalla cartella corrente. Per script locali fidati proporrei di consentirlo; se gli script arrivano da terzi, occorre decidere una cartella consentita. Vanno inoltre convertiti in errori leggibili file mancanti, directory al posto di file, permessi insufficienti e contenuti non decodificabili.

In @test_calc.py ci sono test del valutatore; aggiungerei test dell’esecuzione degli script con file temporanei:

- Variabile del chiamante letta dall’incluso e modifica visibile al ritorno.
- Output nell’ordine esatto prima, durante e dopo l’inclusione.
- Inclusioni annidate, ripetute, cicliche e limite di profondità.
- Percorsi con spazi, sintassi invalida ed errori di lettura.
- Errore nell’incluso: output, stato residuo, prosecuzione e codice d’uscita.
- Regressione di assegnazioni e identificatori come `include_count`.

Prima di fissare il comportamento servono due tue scelte:

1. **Percorsi relativi:** consiglio rispetto al file che contiene la direttiva, usando la directory corrente per lo script ricevuto da stdin. Alternativa: sempre rispetto alla directory corrente.
2. **Errori nell’incluso:** consiglio continuare con le righe successive e segnalare il fallimento finale, coerentemente con gli script attuali. Alternative: interrompere solo il file incluso oppure fermare tutto.
```
